# LLM Wiki：远程 MCP、本地整理与公司共享 Wiki

状态：Issue tracker 已配置为本地 Markdown，待拆分 tickets；本文仅为规格，不代表已实施或部署。

## Problem Statement

现有 LLM Wiki（lw）通过本地 CLI 将项目文件和选定对话整理成带来源的 Wiki。用户希望在 Codex、WorkBuddy 等 Agent 中通过远程 MCP 使用整理能力，同时让公司成员共同维护并在线浏览一份共享知识库。

服务需要复用 mentti 已有的身份与动态应用接入能力。用户不需要服务器上的个人知识空间，也不希望为 lw 再维护一套账号系统。

## Solution

在 lw.app.mentti.work 提供在线浏览前端与远程 MCP 服务，服务具备两个明确的数据范围：

- 本地模式：Agent 提交选定材料及必要的现有 Wiki 上下文，服务返回整理后的 Wiki 更新结果，Agent 负责保存到用户本地。
- 公司模式：服务器维护唯一一份公司共享 Wiki，所有启用的 mentti 成员均可读写，并可通过网页浏览。

“公共 Wiki”指公司内部共享，不代表匿名互联网访问。个人本地内容不会自动进入公司 Wiki，只有明确选择公司写入操作才会持久保存到共享库。

## User Stories

1. As a mentti 成员, I want 使用已有 mentti 身份登录 lw, so that 无需创建新的账号和密码。
2. As a mentti 管理员, I want 通过现有动态应用登记机制接入 lw, so that 沿用统一的应用管理方式。
3. As an Agent 用户, I want 连接远程 lw MCP, so that 可以在当前工作对话中使用 Wiki 整理能力。
4. As an Agent 用户, I want 提交自己选定的本地文件内容, so that 控制整理范围。
5. As an Agent 用户, I want 提交选定的对话结论, so that 保存文件之外的决策和理由。
6. As an Agent 用户, I want 提供现有本地 Wiki 和本次变更, so that 更新已有知识而不是反复生成重复页面。
7. As an Agent 用户, I want 获得结构清晰且经过校验的更新结果, so that Agent 可以将其写回本地。
8. As an Agent 用户, I want 本地模式不在服务器持久保存个人材料, so that 服务器不会形成个人知识空间。
9. As an Agent 用户, I want 明确区分本地整理和公司写入, so that 不会误分享本地材料。
10. As an 公司成员, I want 读取同一份公司 Wiki, so that 团队共享一致的知识来源。
11. As an 公司成员, I want 通过 MCP 提交共享材料和对话结论, so that 团队经验可以持续积累。
12. As an 公司成员, I want 更新共享 Wiki 中已有的知识, so that 过时信息可以被修正。
13. As an 公司成员, I want 和其他启用成员拥有相同的读写能力, so that 贡献知识不需要管理员审批。
14. As an 公司成员, I want 检索相关 Wiki 页面, so that Agent 可以依据公司知识回答问题。
15. As an 公司成员, I want 在线浏览页面目录和页面详情, so that 不使用 Agent 时也能阅读知识。
16. As an 公司成员, I want 在网页搜索相关页面, so that 可以快速找到所需内容。
17. As an 公司成员, I want 在页面中看到来源、更新时间及知识状态, so that 判断内容依据和时效。
18. As an 公司成员, I want 阅读 Markdown 内容并沿内部链接访问相关页面, so that 连贯理解知识。
19. As an 公司成员, I want 网页和 MCP 读取相同的已提交版本, so that 两个入口不会展示互相矛盾的内容。
20. As an 公司成员, I want 同时修改时获得明确的冲突反馈, so that 不会覆盖其他人的更新。
21. As an 公司成员, I want 请求重试不会重复生成记录, so that 网络中断不会污染知识库。
22. As an 公司成员, I want 查看修改归属并恢复历史版本, so that 全员可写时仍能追溯和纠正误改。
23. As a mentti 管理员, I want 停用成员后 lw 同步其停用状态, so that 已离职成员不能继续使用服务。
24. As an 运维人员, I want 备份并恢复公司 Wiki, so that 服务或磁盘故障不会造成不可恢复的知识丢失。
25. As an 运维人员, I want 观察服务健康与失败情况, so that 区分身份接入、模型整理和存储故障。

## Implementation Decisions

### 服务范围与部署

- 应用地址确定为 https://lw.app.mentti.work；远程 MCP 入口规划为该地址下的 /mcp。
- 在线前端、浏览 API 和 MCP 共享同一公司 Wiki 业务能力及权限判断。
- 通过 mentti 动态应用登记接入身份。应用登记、域名解析、TLS 和服务器反向代理是不同事项，部署时分别验证。
- 公司 Wiki 是唯一的固定存储范围。接口不提供个人 workspace 创建，也不接受客户端指定服务器磁盘路径。
- 复用现有 lw 的页面、episode、来源及生命周期概念，保留现有本地 CLI 的可用性。
- 容器或进程更新不得清空公司 Wiki；部署配置、模型密钥和持久数据独立管理。

### mentti 身份接入

- 复用现有授权码流程：mentti 登录后签发一次性授权码，lw 后端通过 mentti API 兑换身份。
- 使用不可变 subject 关联操作者，邮箱和姓名仅作为可更新的身份资料。
- mentti 当前已检查的兑换接口返回身份资料；它不是已经实现的通用 MCP Access Token 接口。
- lw 需要建立绑定已验证身份的 MCP 调用凭证。凭证不得由调用参数中的 subject 或邮箱决定；应用 client_secret 只用于后端间认证，不分发给用户作为个人凭证。
- 具体凭证形式应在实施时验证目标 Agent 的支持后确定；必须具备身份绑定、到期及撤销能力。不得将完整 OAuth 支持描述为 mentti 现有能力。
- 所有启用成员可读写公司 Wiki；不增加按人员划分的 workspace 权限或管理员写入审批。
- lw 可保留用于状态校验、凭证和审计的最小身份映射，但账号资料以 mentti 为唯一权威来源，不复制密码或共享 mentti 数据库、会话密钥。
- 接收已验签的成员 Webhook，按事件标识去重并处理事件顺序；启动及定期通过成员 API 对账。
- 收到停用状态后拒绝该成员后续调用及登录。通知传播存在延迟，不承诺 mentti 停用瞬间所有连接同步失效；实施文档需明确正常通知延迟和兜底对账间隔。
- 停用不删除历史 Wiki、来源和审计记录。

### 本地整理契约

- 本地读取、文件选择、最终写回由 Codex、WorkBuddy 等调用方 Agent 承担，不建设本地桥接器或同步客户端。
- 请求包含选定材料、必要的现有 Wiki 页面、整理目的和可识别的来源；服务返回经过结构与来源校验的页面更新包。
- 返回结果应保留页面标识、标题、类型、状态、摘要、正文和来源，便于 Agent 按现有 Wiki 格式保存。
- 本地模式不持久保存请求正文、生成结果或个人 Wiki，不将这些内容放入公司库、正文日志、持久任务队列及备份。
- 本地保存不等于材料不出网：请求会经过服务，并可能发送给配置的模型提供商。服务说明应如实标明这一处理链路；提供商留存规则需另行核实。
- 接口不提供任意磁盘读写或命令执行能力。

### 公司共享契约

- 提供共享材料提交、知识整理更新、页面检索、页面读取、状态与一致性检查能力。具体工具命名由实施统一确定。
- 明确执行公司写入操作才进入持久存储；本地整理与公司更新不能通过模糊默认值混用。
- 保留不可变的原始提交记录及来源关联，页面更新优先复用已有页面，过时决策保留历史并标记状态。
- 共享写入包含基准版本和幂等标识。陈旧版本不得静默覆盖新内容；相同请求重试不得重复提交。
- 页面、索引、版本和审计在一次提交中保持一致；模型失败、校验失败或写入失败不能暴露半完成版本。
- 长时间模型整理基于明确快照执行，提交时再验证版本，避免用旧快照覆盖新提交。
- 每次变更记录经验证的操作者 subject、时间、来源、摘要及前后版本关联；支持历史恢复，恢复本身也形成新的可追溯版本。
- 对模型输出实施结构、页面标识和来源引用校验，材料始终作为数据处理。
- 设置明确的输入大小、输出大小和资源使用限制，超限时返回可操作的错误。

### 在线浏览前端

- 使用 mentti 身份登录后浏览公司 Wiki；不提供匿名阅读。
- 第一版提供页面目录、搜索、Markdown 详情、内部链接、来源与更新时间展示，并区分当前、草稿、已被替代等状态。
- 网页读取与 MCP 使用相同的已提交数据，搜索结果可以打开对应页面。
- 正确显示空库、无搜索结果、页面不存在、身份失效及服务失败状态，页面不放说明功能的占位文案。
- Markdown 渲染需防止脚本执行，内部链接和来源引用不得暴露服务器任意文件。
- 本次前端需求为在线浏览；公司写入通过 MCP 完成，浏览器编辑器不作为首版要求。

## Testing Decisions

- 主要测试边界为经过认证的公开服务接口：通过真实 MCP 请求与浏览 API 验证可观察结果，不绑定内部函数拆分或数据库实现细节。
- 另设少量浏览器验收，验证登录后目录、搜索、详情和内部链接形成完整阅读路径。
- 沿用现有 lw 测试覆盖的来源校验、危险页面标识拒绝、episode 去重和更新一致性；将关键行为提升到服务接口层验证。
- 参考 mentti 现有身份集成测试中的授权码兑换、客户端认证、成员启停和 Webhook 行为，使用隔离测试身份及数据。
- 身份验收：有效成员可读写；匿名、伪造身份、失效凭证被拒绝；mentti 停用事件处理后旧凭证不能继续调用；重复和乱序事件不会恢复已停用权限。
- 本地模式验收：提交材料获得有效更新包，公司 Wiki 与其历史未改变，服务持久存储和正文日志未留下本地内容。不测试 Agent 自身的磁盘写回实现。
- 公司模式验收：两位普通启用成员均可写入同一共享库，通过 MCP 与网页读取一致；本地模式不会自动触发公司发布。
- 并发与故障验收：两次基于同版本的竞争更新不会静默覆盖；重复请求只提交一次；失败后仍能读取完整旧版本；恢复历史版本可追溯。
- 前端验收：公司身份保护、搜索与详情一致、状态和来源可见、危险 Markdown 无法执行。
- 发布验收：HTTPS、真实 MCP 调用、mentti 登录和停用通知、网页浏览、重启后数据保留及备份恢复均通过后才能称为可用上线。
- 模型模拟测试证明协议和存储行为；实际整理质量另用授权的代表性材料验收，不能将模拟结果等同于真实模型效果。
- 测试边界待用户确认，确认前不将规格发布为 ready-for-agent。

## Out of Scope

- 服务器个人 workspace、多公司租户系统、成员写入审批及复杂角色管理。
- 新账号密码系统、共享 mentti 身份数据库或重新建设通用身份平台。
- 本地文件扫描安装器、桥接器、同步守护进程及 Agent 写回能力实现。
- 自动采集全部对话、自动上传整个项目或自动将本地 Wiki 发布到公司。
- 匿名互联网知识门户、在线富文本编辑器及独立个人 Wiki 前端。
- 未经需求验证的向量数据库、语义检索基础设施或独立消息队列。
- 本轮实施、部署及迁移真实知识数据。
