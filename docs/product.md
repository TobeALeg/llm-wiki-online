# 产品定义

## production

### 用户是谁

- 使用本地 Agent 的个人用户：选择项目材料和对话结论，整理后由 Agent 写回本地 Wiki。
- 公司内部启用的 mentti 成员：共同读取和维护唯一的公司 Wiki。
- 运维人员：负责身份、模型、存储、备份和服务健康。

### 核心价值

把可追溯的知识整理能力放在清晰的信任边界内：个人材料默认只返回整理结果，公司材料只有明确提交后才进入共享 Wiki。

### 产品原则

1. 本地整理和公司写入是两个明确操作，不能靠默认值混用。
2. 材料、页面、版本和操作者都要可追溯；模型输出在写入前必须通过契约校验。
3. 公司 Wiki 只有一个固定存储范围，成员身份由 mentti 的不可变 subject 归属。
4. 失败、重试和并发必须是可观察且可恢复的，不能静默覆盖或留下半完成状态。
5. 服务器不替调用方读取本地路径、不执行调用方命令，也不把本地整理请求持久化。

### 不做什么

- 不建设个人服务器 workspace、匿名公共 Wiki、独立账号密码系统或复杂角色审批。
- 不自动扫描、上传或发布调用方的整个项目和本地 Wiki。
- 不实现 Agent 的本地写回、文件扫描安装器或同步守护进程。
- 不把 mentti 授权码兑换描述成通用 OAuth，也不复制密码、mentti 数据库或会话密钥。

### 用户体验路径

1. 本地 Agent 选择材料、对话结论和现有页面，调用本地整理能力。
2. 服务返回带稳定页面标识、摘要、正文、状态和来源的更新包，Agent 自行写回本地。
3. 成员通过 mentti 登录并获取到期、可撤销的远程 MCP 凭证。
4. 成员明确选择公司提交；服务在版本基准仍有效时一次性保存材料、页面、索引和审计。
5. 成员通过 MCP 或登录后的网页读取相同的已提交版本；冲突和历史恢复都产生新的可追溯版本。

## ux

- 页面优先展示真实 Wiki 内容、来源、更新时间和知识状态，不放解释产品功能的占位文案。
- 空库、无结果、页面不存在、身份失效和服务失败都有明确可行动的状态。
- 本地整理结果在界面和 API 命名上与公司提交明确区分，避免误分享。
